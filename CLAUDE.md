# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

ADS Semester 7 — design of a SIMD vector accelerator for 3D sound-source localization, targeting a Digilent Zybo (Zynq-7000: Cortex-A9 PS runs a C driver, PL holds the accelerator). Four mics in a tetrahedron; three independent centered Block-LMS filters (Mic2/3/4 vs reference Mic1) estimate TDOA delays tau_21, tau_31, tau_41. The architecture is based on Mahmood & Al-Jbaar, "Design and implementation of SIMD Vector Processor on FPGA" (IEEE ISIICT 2011). `onur-comparch-fall2025-lecture29a-simd-afterlecture.pdf` is background lecture material on SIMD.

The accelerator is meant to be vendor-neutral Verilog behind standard AXI4-Lite / AXI4-Stream interfaces (inferred RAM and multipliers); Zynq-specific pieces (AXI DMA, interconnect) sit outside it.

Not a git repo. No build system, tests, or dependency manifest; there is no HDL in the repo yet.

## Layout

- `ISA_Design.md` — the ISA/microarchitecture spec, v1.1 (the main design artifact). Starts with a changelog of what was wrong in v1.0 and why.
- `simulation_py/realtime_simulation.py` — Python **golden reference model**. `RealTimeCenteredNLMS.process_block()` is exactly what each PE must compute per block.
- `simulation_py/fixed_point_model.py` — bit-accurate fixed-point model of one PE (Q1.15 samples, Q2.30 reversed weights, 25×18 multiply, 48-bit accumulate).
- `simulation_py/isa_sim.py` — assembler + instruction-level simulator of the 3-PE cluster (ISA v1.1) with a timing model; contains the 78-instruction microprogram and verifies it bit-exact against `fixed_point_model.py`.
- `simulation_py/feasibility_run.py` — runs float / fixed-point variants over the full scenario → `simulation_py/results/feasibility.npz`.
- `simulation_py/tracking_study.py` — μ vs block-NLMS tracking-lag study → `results/tracking_study.txt`.
- `simulation_py/simulation.ipynb` — exploratory notebook (sample LMS → centered LMS → centered Block LMS, static source).
- `presentation/` — slide figures (`figures/*.png`, generated by `plot_results.py`, `draw_*.py` using `diagram_kit.py`) and local HTML explainers (`explainers/`).

## Running

Dependencies: `numpy`, `scipy`, `matplotlib`.

```bash
python3 simulation_py/realtime_simulation.py   # golden model demo (sleeps per block; slow)
python3 simulation_py/feasibility_run.py       # ~1 min, writes results/feasibility.npz
python3 simulation_py/isa_sim.py 600           # ISA program vs fixed-point model, prints cycles/block
python3 presentation/plot_results.py           # needs feasibility.npz
python3 presentation/draw_microarch.py         # likewise draw_isa.py, draw_memory.py, draw_feasibility.py
```

All commands work from the repo root: Python puts each script's own directory on `sys.path`, and file paths are resolved relative to the scripts. `source2.wav` is 48 kHz stereo; only channel 0 is used.

## How the Python model maps to the hardware (v1.1)

| `process_block()` step | ISA phase | Key instructions |
|---|---|---|
| `x_full = [x_history | x_block]`, `d_delayed = d_full[:B]` | circular X/D rings written by the input writer (no copies) | `SYNC 1`, `AGU_SET … circ=1` |
| `y = X @ w` | Phase 1 | `WLD`, `VMAC`, `VREDUCE`, `WSLIDE`, `SST` |
| `e = d_delayed - y` | Phase 2 | `VLD`, `VSUB`, `VST` |
| `g = X.T @ e` | Phase 3 | `WLD`, `VMAC`, `VREDUCE`, `WSLIDE`, `SST` |
| `w += (mu/B) * g` | Phase 4 | `VSCALE`, `VADD` (÷B is the `VREDUCE` shift) |
| `center_tap - argmax(|w|)` | Phase 5 | `PKCLR`, `PKMAX`, `PKOUT`, `IRQ` |

Things to keep in mind:
- `X[i] = x_full[i+L : i : -1]` is reversed. The hardware stores **w reversed** (`w_rev[k] = w[L-1-k]`) so row i is `x_full[i+1 .. i+L]` and column k is `x_full[k+1 .. k+B]` (both ascending); tau = `argmax|w_rev| - (L-1-L/2)`. Reading ascending without reversing w flips the sign of tau.
- All vector accesses are 16-aligned (the input writer's XOFF = L-1 puts `x_full[1]` on a 16-word boundary); the sliding window moves one sample per row/column via `WSLIDE`.
- `w_rev` persists across blocks; the block base A7 persists too (don't reset it per block).
- Fixed-point formats and the verified cycle count (2 695 cycles/block) are in ISA_Design.md §4.4 and §10; if you change the ISA or the microprogram, re-run `isa_sim.py` and keep the doc's listing in sync.
- The `realtime_localization_loop()` default args (B=2048, L=256) differ from the values `__main__` and the ISA use (B=128, L=64). μ = 0.05 lags the moving source; simulation favours μ = 0.5 or block-NLMS.
