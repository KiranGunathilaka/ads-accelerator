Instruction set

Instruction set architecture, v1.1

What an instruction set is here, the format and why each field is that wide, all 32 instructions in plain words, the addressing modes, where every shift amount comes from, and the exact program the simulator runs, phase by phase and cycle by cycle.

What an instruction set is, for this accelerator

An instruction set (ISA) is the list of commands the accelerator understands and how each one is written as a 32-bit number. Our program is written in these commands. It runs on the accelerator's own control unit, not on the ARM. The ARM writes the program (78 words) into the instruction memory once at start-up; after that it runs once per block of audio by itself.

  • One instruction, three PEs. The control unit reads one instruction and sends it to all three PEs at the same time (that is SIMD). Each PE works on its own microphone pair. Inside a PE there are 16 lanes, so one multiply-accumulate instruction does 16 × 3 = 48 multiply-adds.
  • Four kinds of registers. V0–V7 hold 16 numbers each (one per lane). W0–W7 are the 8 chunks of the window register (16 samples each). S0–S7 hold one number each. A0–A7 hold memory addresses, and are shared by all PEs because all PEs use the same addresses.
  • From text to bits. The assembler in isa_sim.py turns a line such as VMAC.C W0, V4, sh=7 into the number 0x0010400F. That number is what the hardware decodes.

Instruction format

OPCODE[31:27] · 5 bits
DST[26:22] · 5
SRC1[21:17] · 5
SRC2[16:12] · 5
IMM12[11:0] · 12 bits

This layout is v1.0's, unchanged. Every instruction is 32 bits with the same five fields at the same positions, so the decoder is mostly wiring, and one instruction comes out of the 32-bit-wide instruction memory every cycle. OPCODE[4:3] picks one of four groups of eight, which tells the control unit which unit the instruction belongs to before the rest is decoded.

FieldBitsWhy this width
OPCODE520 instructions run every block, more than 4 bits (16) can encode. 5 bits is the minimum, and gives 32 codes.
DST, SRC1, SRC25 eachRegisters need codes 0–7, plus 8 for ZERO and 8–15 for the window chunks. 4 bits would do; 5 keeps v1.0's layout and leaves room for 16 vector registers.
IMM1212Largest values: base address 0x540 (1 344), loop count 128, PKOUT offset 31, post-increments ±16. Unsigned range 0–4 095, signed ±2 047. It also carries small sub-fields (shift amounts, flags, the CSR index).

What a register field means depends on the opcode

Field kindCodes 0–7Code 8 and up
vector sourceV0–V78–15 = W0–W7, the window chunks (VMAC only)

addressA0–A78 = ZERO (base for AGU_SET)
CSRindex in IMM12[3:0]

v1.0 used one global 2-bit tag in every register field (00 vector, 01 scalar, 10 CSR, 11 immediate). The CSR tag sat in bits [4:3] while the CSR index needed bits [3:0], so bit 3 was used twice and only 8 of the 16 CSRs could be named. Letting the opcode decide what a field means removes the tag bits altogether.

Addressing modes

An addressing mode is the rule for working out which memory word an instruction reads or writes. All addresses come from the address registers A0–A7, computed by the shared address generator (AGU).

ModeExampleIn plain wordsAddress arithmeticUsed for
Post-incrementVLD V4, [A2]+16use the address in A2, then move A2 on by 16, ready for the next chunkaddress = A2; A2 += 16 walking through w, y, e, g in 16-word chunks; single-word stores with +1
Base + offsetAGU_SET A0, A7, X_RINGset A0 to “where this block starts” (A7) plus the start of the X ringA0 = A7 + X_RINGpointing at this block's data inside a ring
Circular… circ=1when the pointer runs off the end of the 512-word ring, it continues at the start, like a clock handkeep bits [12:9]; add only in bits [8:0] the input rings, so old samples never need to be copied
Sliding windowWSLIDE [A0], len=64shift the window along by one sample and fetch just the one new sample at A0read M[A0]; A0 += 1 next row (Phase 1) or column (Phase 3) of X with one memory read

Why these are enough. Once w is stored reversed, every access in the algorithm is an aligned 16-word chunk, a single word, or “the same window moved by one”. There are no strides, gathers or unaligned vectors, so the address generator is one adder and a mask. The lecture's general vector machine needs a stride register (VSTR), a length register (VLEN) and a mask register (VMASK); this algorithm needs none of them, which is also how MMX was designed (fixed width, stride always 1).

Why storing w reversed makes this work: a tiny example

Take L = 4 taps and B = 3 outputs, so x_full = x0 … x6. The golden model builds X[i] = x_full[i+L : i : −1]:

RowX[i, 0]X[i, 1]X[i, 2]X[i, 3]y[i] = X[i] · w
0x4x3x2x1x4·w0 + x3·w1 + x2·w2 + x1·w3
1x5x4x3x2x5·w0 + x4·w1 + x3·w2 + x2·w3
2x6x5x4x3x6·w0 + x5·w1 + x4·w2 + x3·w3
  • Rows run backwards in memory. Store w_rev = [w3, w2, w1, w0] and row 0 becomes x1·w_rev[0] + x2·w_rev[1] + x3·w_rev[2] + x4·w_rev[3]: memory read forwards from x1. Row 1 starts at x2, row 2 at x3. Each row is the previous one moved by one sample, which is what WSLIDE does.
  • Columns: column 3 of X is x1, x2, x3 and column 0 is x4, x5, x6. In w_rev order (k = L−1−j), column k starts at x_full[k+1]: again forwards and again moving by one sample. So Phase 3 uses the same window hardware with length B instead of L.
  • v1.0 read rows forwards from x_full[0] with w in normal order: x0·w0 + x1·w1 + x2·w2 + x3·w3. That is a different filter (mirrored and shifted by one sample), so it converges to a mirrored spike. Running the same audio through v1.0's access pattern reported +7 where the true delay is −7.

Where every shift amount comes from

The shift fields in VMAC, VREDUCE and VSCALE exist because the datapath is fixed point. x, d, y, e are Q1.15 (15 fractional bits); w and g are Q2.30 (30 fractional bits); μ is Q1.15.

StepInstructionFormats in → outShift and why
P1 multiplyVMAC W, V, sh=7x (Q1.15) × w (Q2.30 → Q2.23) → 38 fractional bits, 41-bit productsh = 7: the DSP48E1 A port is 25 bits, so the 32-bit weight drops its 7 lowest bits
P1 accumulate4 × VMAC + tree64 products → at most 47 bitsfits the 48-bit P register; the adder tree is ~52 bits wide
P1 resultVREDUCE sh=23, rnd, sat1638 fractional bits → Q1.15 38 − 15 = 23; round to nearest; clamp to 16 bits
P2 errorVSUB sat16Q1.15 − Q1.15 → Q1.15no shift; clamp
P3 multiplyVMAC W, Vx (Q1.15) × e (Q1.15) → 30 fractional bits, 32-bit productno shift: e already fits the A port
P3 accumulate8 × VMAC + tree128 products → at most 39 bits—
P3 resultVREDUCE sh=7sum → mean gradient, Q2.307 = log2 128: dividing by B is a shift, so μ/B needs no divider
P4 stepVSCALE pre=7, post=8g (Q2.30 → Q2.23) × μ (Q1.15) → 38 fractional bits → Q2.30pre = 7 for the 25-bit A port; post = 38 − 30 = 8
P4 addVADDQ2.30 + Q2.30clamp at 32 bits
P5 peakPKOUT 31index → τ31 = L−1−L/2, because w is reversed

One Phase-1 row, cycle by cycle

The scoreboard lets an instruction issue only when its inputs are ready. This is where the 12 cycles per row go:

CycleIssuesIn plain wordsWhy it waits (or not)
0VMAC.C W0, V4, sh=7multiply samples 1–16 of this row by weights 0–15 and start new running sumsnew sum for row i
1–3VMAC W1…W3, V5…V7the same for the next 48 samples and weights, adding to the sumsback-to-back: the DSP accumulates internally
4–5stallwaitVREDUCE needs VACC; the DSP pipeline takes 3 cycles
6VREDUCE S1, sh=23add the 16 sums into one number y[i]adder tree starts; y[i] ready at cycle 11
7WSLIDE [A0], len=64move the window on by one sample for the next row doesn't need S1, so it goes at once
8–10stallwaitSST needs S1 from the 5-cycle tree
11SST S1, [A3]+1write y[i] to memorythe loop jumps back with no bubble

5 of the 12 cycles are stalls. Storing y[i−1] during row i's stall slots (software pipelining) would bring a row to about 8 cycles. It isn't needed: the whole block already takes 1 % of the time available. The Phase-3 column has the same shape: 8 VMACs, 2 stalls, VREDUCE, WSLIDE, 3 stalls, SST = 16 cycles.

v1.0 for comparison. v1.0's Phase-1 listing spent 32 instructions per row: 4 × (VLD, VLD, VMAC, AGU_INC, AGU_INC, LOOP_DEC), plus clears, the reduce, the store, the slide and the loop. v1.1 needs 7. The saving comes from post-increment, keeping w in registers, VMAC.C, the window register and the zero-overhead LOOP.
