The basics, from zero

Everything the other pages assume: the problem, every symbol (μ, B, L, τ …), how the filter learns, and every hardware word. No background needed.

How to use this page. Sections 1–8 explain the idea from the start, in order. Section 9 is a glossary: every underlined term on the other pages links to its entry here.

1. What we are building

We want to know where a sound comes from. Four microphones sit at the corners of a small pyramid (a regular tetrahedron with 10 cm edges). Sound travels at about 343 m/s, so it reaches the microphones at slightly different times: the nearer one hears it first.

The time difference between two microphones is the TDOA (time difference of arrival). We measure three of them, each against Mic 1: τ21 (Mic 2 vs Mic 1), τ31 and τ41. From those three numbers the ARM processor computes where the source is (triangulation).

The accelerator does one job: it finds τ21, τ31 and τ41 from the live microphone signals, again and again, every 2.7 ms. Everything else (setup, triangulation) is C code on the ARM.

2. Samples, and why delays are counted in samples

  • A microphone produces a voltage that rises and falls with the sound. A converter measures it at regular moments. Each measurement is a sample: a 16-bit whole number.
  • We take 48 000 samples per second. That is the sample rate, fs = 48 kHz: one sample every 1/48 000 s = 20.8 µs.
  • In 20.8 µs sound travels 343 m/s × 20.8 µs = 7.15 mm. So delays are measured in whole samples, and one sample of delay means about 7 mm more path.
  • Across 10 cm the largest possible delay is 0.1 m ÷ 343 m/s = 292 µs ≈ 14 samples. Every τ lies between about −14 and +14.
  • Sign: τ21 = (arrival time at Mic 2) − (arrival time at Mic 1). Positive: Mic 2 hears the sound later (it is farther away). Negative: earlier.

4. What a filter is

A FIR filter (finite impulse response) makes each output sample as a weighted sum of the last L input samples:

y[n] = w[0]·x[n] + w[1]·x[n−1] + w[2]·x[n−2] + … + w[L−1]·x[n−L+1]

Each weight is a tap. Each tap costs one multiply and one add, a multiply-accumulate (MAC), so a 64-tap filter costs 64 MACs per output sample.

The key trick. If every weight is 0 except w[5] = 1, the output is the input delayed by 5 samples: y[n] = x[n−5]. A filter can represent a delay. So if a filter learns to turn Mic 2's signal into Mic 1's, its weights become a single spike, and the position of the spike is the delay.

5. How the filter learns: LMS

We don't know the delay, so we can't write the weights down. LMS (least mean squares) lets the filter find them by guessing and correcting, thousands of times per second:

  1. Predict. Run the filter on Mic x to get y, a guess of Mic 1.
  2. Measure the error. e = d − y (d is Mic 1).
  3. Correct. Nudge every weight in the direction that makes the error smaller. For tap j the nudge is μ × e × (the input sample that tap j used). Taps whose inputs line up with the error grow; the others barely move.
  4. Repeat with the next samples.

After enough updates the weights settle into a spike at the tap that lines Mic x up with Mic 1. The name “least mean squares” comes from what the procedure minimises: the average of e².

What μ does

μ (“mu”, the step size) scales every correction. With μ = 0.05, the value in the original Python, each block moves the weights only a little. When the source moves, the spike follows about 3.7 s late and 47 % of estimates are within ±1 sample. With μ = 0.5 the lag drops to 1.7 s and 85.6 % are within ±1 sample. Too large a μ makes the weights overshoot and jitter, and past a limit they blow up. μ is a register the ARM writes (the MU CSR), so it can change without new hardware.

NLMS

Normalised LMS divides the step by the input's power (L × Px), so loud and quiet sounds adapt at the same speed, and it is stable for any 0 < μ < 2. The Python class is named “NLMS” but actually uses μ/B, which is not normalised. Our study shows true block NLMS (μ = 0.64) reaches 88 %.

6. “Centered”: allowing negative delays

A filter can only use past samples; it can't look into the future. Suppose Mic 2 hears the sound later than Mic 1 (τ21 > 0). Then the Mic 2 sample that matches Mic 1's current sample has not arrived yet, and the filter would need a future input.

The fix is to delay Mic 1 by CT = L/2 = 32 samples before comparing. Now the spike sits at tap j = 32 − τ, which lies between 0 and 63 for any τ from −31 to +32. That is why the delay is read as τ = 32 − (spike position), and why L = 64 taps cover about ±32 samples: more than the ±14 that 10 cm allows. In hardware the delay of Mic 1 costs nothing: the input writer just stores Mic 1 32 places further along.

7. Block LMS: why 128 samples at a time

Plain LMS updates the weights after every sample, so sample n+1 has to wait for sample n's update. That chain is sequential and hard to run in parallel.

Block LMS freezes the weights for a block of B = 128 samples. Inside a block all 128 predictions use the same weights, so they are independent and can be computed in parallel. Then the weights are updated once, with the average correction of the whole block. Per block, each filter runs five phases:

PhaseIn wordsMathWork
1 Filterpredict all 128 outputsy = X w128 × 64 = 8 192 MACs
2 Errorcompare each prediction with Mic 1e = d_delayed − y128 subtractions
3 Gradientwork out the correction for each of the 64 weightsg = Xᵀ e8 192 MACs
4 Updateapply the correctionw ← w + (μ/B)·g64 MACs
5 Peakfind the largest weight and turn it into ττ = 32 − argmax|w|64 compares

X is the 128 × 64 table of input windows: row i holds the 64 most recent Mic x samples at moment i. X w means “for every row, multiply by the weights and add up”: a matrix–vector product. Xᵀ e uses the same table by columns. Phases 1 and 3 are 99 % of the work, and both read rows or columns of the same table. The hardware is built around that.

Why B = 128 and L = 64

These are the values the golden model's demo uses, and we kept them. They also suit the hardware well:

  • L = 64 covers delays up to about ±32 samples, more than twice the ±14 that 10 cm allows.
  • Both are multiples of 16, the number of lanes: a row (64 taps) is exactly 4 vector operations and a column (128 samples) exactly 8.
  • B is a power of two, so “divide by B” is a right shift by 7 bits, which costs nothing in hardware.
  • 64 weights fit in 4 vector registers and 128 errors in 8, so they stay in registers for a whole phase.
  • B = 128 at 48 kHz gives a new delay estimate every 2.67 ms (375 per second).

A larger B gives fewer, smoother updates; a larger L gives a wider delay range and more work. The accelerator is busy only 1 % of the time, so L = 256 would still fit.

8. Numbers in hardware: fixed-point

Fractions can be stored as floating-point (a number plus an exponent, like 1.23 × 10⁻⁴) or as fixed-point (a whole number with an agreed scale). The FPGA's multiplier blocks multiply whole numbers, so fixed-point is far cheaper.

A Q-format name says how many bits sit before and after the binary point:

  • Q1.15: 16 bits, 1 sign bit and 15 fraction bits. Holds −1 to just under +1 in steps of 1/32 768; the value is the stored integer ÷ 32 768. Audio samples, y and e use it. μ = 0.5 is stored as 16 384.
  • Q2.30: 32 bits, range −2 to +2, steps of about 10⁻⁹. Used for the weights, because each update is tiny. With 16-bit weights the updates get lost and accuracy drops from 47.0 % to 43.4 %.
  • 48-bit accumulator: the DSP48E1's P register. Large enough that sums of 64 or 128 products never overflow.

Saturate: if a result is too big for its format, clip it to the largest value instead of letting it wrap round to a negative number. Round: add half a step before dropping bits. Shift right by k: divide by 2k.

Result: fixed-point gives exactly the same τ as floating-point on 99.6 % of 47 547 blocks, with identical accuracy.

9. Glossary

Grouped by topic. “Here:” notes how the term applies to our design.

Signal-processing words

TDOA (time difference of arrival)
The difference in arrival time of the same sound at two microphones. Three TDOAs locate a source in 3-D.Here: τ21, τ31, τ41 in samples.
Sample
One measurement of the microphone signal, a 16-bit whole number. Taken 48 000 times per second.
FIR filter
Finite impulse response filter: output = weighted sum of the last L inputs. See section 4.Here: L = 64 taps.
Tap
One weight of a FIR filter and the delayed input sample it multiplies.
LMS (least mean squares)
A way for a filter to learn its weights by repeatedly nudging them to shrink the error. See section 5.
NLMS (normalised LMS)
LMS whose step is divided by the input power, so loud and quiet input adapt at the same speed. Stable for 0 < μ < 2.Here: Optional: the ISA keeps SDIV for it. Study: 88 % within ±1 sample.
Block LMS
LMS that freezes the weights for a block of B samples, then updates once. Makes the B outputs independent, so they can be computed in parallel. See section 7.Here: B = 128.
Centered filter
The reference is delayed by L/2 so the learned spike can sit on either side of the center: negative and positive delays both fit. See section 6.Here: CT = 32.
Gradient
The direction to change the weights that reduces the error fastest.Here: g = Xᵀe, computed in Phase 3.
Converge / adapt
The weights settling to their final shape after enough updates.
Tracking lag
How far behind a moving source the estimate runs. Set mainly by μ.Here: μ = 0.05: 3.7 s. μ = 0.5: 1.7 s.
Floating-point / fixed-point
Two ways to store fractions. See section 8.Here: Hardware uses fixed-point.
Q1.15, Q2.30
Fixed-point formats: 1 (or 2) bits before the binary point, 15 (or 30) after. Q1.15 holds −1 … +1 in 16 bits; Q2.30 holds −2 … +2 in 32 bits.Here: Samples, y, e, μ: Q1.15. Weights and gradient: Q2.30.
Saturate, round, shift
Saturate: clip a too-large result to the largest value instead of wrapping to a negative number. Round: add half a step before dropping bits. Shift right by k: divide by 2k.Here: Division by B = 128 is a shift by 7.

The board and the FPGA

Zybo
A Digilent development board built around a Xilinx Zynq-7000 chip.Here: Z7-10 (smaller) or Z7-20 (larger).
Zynq-7000
One chip with two halves: a processor side (PS) and an FPGA side (PL).
PS (processing system)
The ARM side of the Zynq: two ARM Cortex-A9 cores, caches and the DDR memory controller.Here: Runs our C driver and the triangulation.
PL (programmable logic)
The FPGA side of the Zynq, where our accelerator is built.
FPGA
A chip full of configurable logic, small memories and multipliers that we wire into our own circuit by writing Verilog.
DDR
The board's main memory (RAM), shared with the ARM.Here: Audio buffers live here.
Verilog, RTL
Verilog is the hardware description language we write. RTL (register-transfer level) is the style: registers, and the logic between them.
IP core, vendor-neutral
An IP core is a ready-made hardware block, such as Xilinx's AXI DMA. Vendor-neutral means our own Verilog uses no Xilinx-only blocks, so it could move to another FPGA.
Synthesis, LUT, FF, Fmax
Synthesis turns Verilog into FPGA resources. LUTs (look-up tables) are the basic logic cells, FFs (flip-flops) store single bits, and Fmax is the fastest clock the result can run at.Here: Not done yet: next step.
DSP48E1
A hard multiplier block in the Zynq-7000: a 25 × 18-bit multiplier, a 48-bit adder and a 48-bit result register (P) that can accumulate.Here: One per MAC lane: 48 + 3 = 51. Z7-10 has 80.
BRAM18
An 18-kilobit on-chip memory block, used here as 512 words × 32 bits.Here: One per memory bank: 3 × 16 + 1 = 49. Z7-10 has 120.
Clock, cycle
The accelerator does one step per clock tick. At 100 MHz one cycle is 10 ns.Here: One block takes 2 695 cycles.

How the ARM and the accelerator talk

AXI
ARM's standard family of on-chip bus protocols.
AXI4-Lite
The simple AXI flavour for reading and writing single registers.Here: The ARM writes settings and the program, and reads τ.
AXI4-Stream
A one-way flow of data words with a ready/valid handshake.Here: Audio comes in this way: one 64-bit word = one sample from each of the 4 mics.
DMA (direct memory access)
A helper block that copies data from DDR by itself, so the ARM does not have to move every sample.Here: Xilinx AXI DMA, or the free Forencich core.
CSR (control and status register)
A register the ARM can read or write through AXI4-Lite.Here: 16 of them: CTRL, STATUS, MU, B, L, TAU21, TAU31, TAU41, …
IRQ (interrupt)
A signal that tells the ARM “results are ready”, so it doesn't have to keep asking (polling).Here: Raised after each block; cleared by the ARM.
Driver
The C code on the ARM that sets up and uses the accelerator.
Cache flush
The ARM keeps copies of memory in its cache. Before the DMA reads a buffer, the ARM writes the cache back to DDR, because the DMA's port does not see the cache.
Back-pressure
When the receiver is not ready, the stream pauses instead of losing data.
Input writer
Our block that receives the audio stream and writes each mic's samples into the right PE memories.Here: Mic 2 → PE0, Mic 3 → PE1, Mic 4 → PE2; Mic 1 → all three.

Parallel processing

SIMD (single instruction, multiple data)
One instruction works on many data items at once.Here: One instruction → 3 PEs × 16 lanes = 48 multiply-accumulates.
PE (processing element)
One copy of the datapath, with its own memory and registers.Here: 3 PEs, one per microphone pair.
Lane
One slice of a PE that handles one number of a vector.Here: 16 lanes per PE, each with one DSP48E1.
Lockstep, broadcast
All PEs get the same instruction and address in the same cycle and do the same thing, each on its own data.
MAC (multiply-accumulate)
acc = acc + a × b. The basic step of a filter.
Vector, scalar
A vector is a group of 16 numbers handled together (one per lane). A scalar is a single number.

Inside the processor

ISA (instruction set architecture)
The list of instructions a processor understands and how each is encoded in bits.Here: 32 instructions, 32 bits each.
Instruction, opcode, field
An instruction is one 32-bit command. Its fields are groups of bits: the opcode says which operation, the others say which registers and constants.
Immediate (IMM)
A constant stored inside the instruction itself, such as an offset, a loop count or a shift amount.Here: 12 bits.
Register, register file
A register is a small, fast storage slot. A register file is a group of them with read and write ports.Here: V0–V7: vectors. S0–S7: scalars. A0–A7: addresses. W0–W7: window chunks.
Program, microprogram
Our program for one block: 78 instructions that the ARM loads into IMEM once.
IMEM
Instruction memory inside the accelerator.Here: 512 × 32 bit, one BRAM18.
PC (program counter)
The address of the next instruction to fetch.
Fetch, decode, issue
Fetch: read the next instruction. Decode: work out what it means. Issue: send it to the units.
Pipeline, latency
Work is split into stages so a new instruction can start every cycle. Latency is how many cycles pass before a result can be used.Here: Loads: 2 cycles. VREDUCE: 5 cycles.
Stall, hazard, scoreboard
If an instruction needs a result that isn't ready yet (a read-after-write hazard), it waits: a stall. The scoreboard tracks when each register will be ready.
Hardware loop (zero-overhead)
LOOP tells the fetch unit to repeat the next few instructions N times. Jumping back costs no cycle, and no branch instruction is needed.
ALU
Arithmetic logic unit: add, subtract, compare. Drawn as a trapezoid with two inputs on the wide side.
Mux (multiplexer)
A switch that passes one of several inputs, chosen by a control signal.
Adder tree
Adds 16 numbers into 1 in four levels: 16 → 8 → 4 → 2 → 1.
Accumulator (VACC)
The register that keeps the running sum of the multiply-accumulates.Here: In each lane it is the DSP48E1's 48-bit P register.
Peak detector
Hardware that finds the largest |w| and where it is.Here: Its position gives τ.
Assembler
A tool that turns text such as VMAC W0, V4 into 32-bit instruction words.Here: Part of isa_sim.py.

Memory and addressing

Word, address
A word is 32 bits. Memory is addressed in words.
AGU (address generation unit)
Computes memory addresses, so the data units don't have to.Here: 8 address registers, shared by all PEs.
Post-increment
Use an address, then add a step to it ready for next time.Here: VLD V4, [A2]+16 loads 16 words, then A2 += 16.
Bank, interleaving
Memory split into 16 independent parts. Word a is in bank a mod 16, so 16 neighbouring words can be read in the same cycle.
Aligned access
A 16-word access that starts at a multiple of 16: exactly one row across the banks.Here: All our vector loads are aligned.
Crossbar, rotator
A large switch network that would allow 16-word loads from any start address. We avoid needing one.
Circular buffer (ring)
Memory used as a loop: the address wraps from the end back to the start. Old data stays where it is.Here: 512 words per mic, per PE.
Sliding-window register
A shift register that holds the current row of X and moves by one sample per row.Here: 128 × 16 bit per PE.
Memory map
Which address ranges hold which data.

10. How the timing numbers are worked out

block period  = B / fs            = 128 / 48 000        = 2.667 ms = 2 667 µs
accelerator   = cycles / clock    = 2 695 / 100 MHz     = 26.95 µs ≈ 27 µs
busy fraction = 27 / 2 667                              ≈ 1.0 %   (≈ 99× headroom)
work needed   = 3 filters × 2 products × L × fs
              = 3 × 2 × 64 × 48 000                     ≈ 18.4 million MACs per second
peak compute  = 48 MACs per cycle × 100 MHz             = 4.8 billion MACs per second

The 2 695 cycles come from the ISA simulator running the real program, including every cycle spent waiting for a result. The count is the same for every block, because the program has no data-dependent branches.
